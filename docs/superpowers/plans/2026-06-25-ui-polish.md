# UI Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lift FeedbackHub from "flat but competent" to polished by unifying its depth language, theme, color, and typography — without changing features, layouts, or logic.

**Architecture:** Establish a single design-token foundation in `app/assets/tailwind/application.css` (two signature themes `fh-light`/`fh-dark`, surface tokens, type scale), introduce one surface primitive (`.surface` / `.surface-overlay` / `.app-bar`), then migrate every component off the three hand-rolled surface treatments onto it. Color and typography discipline are applied as cross-cutting passes.

**Tech Stack:** Rails 8.1, Phlex 2.4 + PhlexyUI, DaisyUI 5.5.19, Tailwind v4 (tailwindcss-rails), Stimulus. Verification via the gstack `browse` headless browser.

## Testing Approach (read first)

This is CSS/visual work. The repo has **no view/component unit tests** — only controller and model tests. Fabricating class-assertion unit tests here would be cheater tests (forbidden by CLAUDE.md). So each task uses a **verification-driven cycle** instead of red-green TDD:

1. Make the change (exact code given).
2. Rebuild CSS: `bin/rails tailwindcss:build` (skip if a `bin/dev` watcher is already running).
3. **Regression gate:** `bin/rails test` stays green (controller tests assert pages render).
4. **Visual gate:** screenshot the affected screens in **both** `fh-light` and `fh-dark` via `browse`, and Read the PNGs to confirm the intended change and no regression.
5. Commit.

Never weaken or delete a passing controller test to make a change "pass."

## Global Constraints

- **No feature, route, model, controller, or business-logic changes.** Visual refinement only.
- **No layout/IA changes** — grids, tabs, page composition stay as-is.
- **Stay on** Phlex + PhlexyUI + DaisyUI 5.5.19. No library swaps, no new gems.
- **Exactly two themes:** `fh-light` (default) and `fh-dark`. No `light`/`dark`/`corporate`/`business`.
- **Glass discipline (performance):** `backdrop-filter` blur is applied ONLY via `.surface-overlay` and `.app-bar` (chrome/overlays). Content surfaces (`.surface`) carry translucency + border + shadow but **no `backdrop-filter`**. A dense feedback grid must not blur per-card.
- **No dead code:** remove old CSS classes once their last consumer is migrated.
- **DateTime:** any timestamps use real `date -u +"%Y-%m-%dT%H:%M:%SZ"` output.
- **Dev DB is sacred:** never reset/drop/seed-destroy the development database. Never kill the dev server.
- Seed login for verification: `admin@feedbackhub.local` / `password`.

- [ ] **Step 1: Update `theme_controller.js`**

Replace the file body with:

```js
import { Controller } from "@hotwired/stimulus"

const VALID = ["fh-light", "fh-dark"]
const LEGACY = { light: "fh-light", corporate: "fh-light", dark: "fh-dark", business: "fh-dark" }

export default class extends Controller {
  connect() {
    this.applyTheme()
  }

  setTheme(event) {
    const theme = event.currentTarget.dataset.themeValue
    if (VALID.includes(theme)) {
      localStorage.setItem("theme", theme)
      this.applyTheme()
    }
  }

  applyTheme() {
    let theme = localStorage.getItem("theme")
    if (LEGACY[theme]) {
      theme = LEGACY[theme]
      localStorage.setItem("theme", theme)
    }
    if (!VALID.includes(theme)) theme = "fh-light"
    document.documentElement.setAttribute("data-theme", theme)
  }
}
```
